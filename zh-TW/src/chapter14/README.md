# Server API

上一章你學會在頁面上用 `useFetch` 跟伺服器拿資料。但那些資料是從哪裡來的？到目前為止，都是別人寫好的 API。

這一章換你自己寫。Nuxt 專案裡除了 `app/` 資料夾，還可以有一個 `server/` 資料夾，放在裡面的程式只會在伺服器上執行。你可以在那裡寫 API：接收瀏覽器送來的資料、存起來、再回傳給頁面。也就是說，同一個 Nuxt 專案就同時有前端和後端。

這一章會做一個「留言板」：

- 列出所有留言
- 填名字和留言送出，畫面立刻更新
- 欄位沒填或太長時，伺服器拒絕並顯示錯誤訊息
- 只有管理者能刪除留言

留言會存在專案裡的 `.data/` 資料夾，用的是 Nuxt 內建的儲存功能，不用另外安裝資料庫。

這一章有一集特別重要：第 6 集「輸入驗證與安全」。只要你寫的 API 會收資料，就一定要懂那一集的觀念。

## 準備環境

留言板用一個新的 Nuxt 專案來做，不沿用第 12 章的 `hello-nuxt` 或第 13 章的 `render-demo`。在你放練習專案的資料夾執行：

```bash
npm create nuxt@latest nuxt-guestbook
```

專案名稱已經寫在指令後面，所以不會再問你要放在哪裡；範本選 **minimal**，其他問題的回答和第 12 章一樣。建好之後進到專案裡：

```bash
cd nuxt-guestbook
```

把 `app/app.vue` 改成只顯示頁面：

```vue
<!-- app/app.vue -->
<template>
  <NuxtPage />
</template>
```

頁面之後會放在 `app/pages/` 資料夾裡，第 1 集會建立它。最後啟動開發伺服器：

```bash
npm run dev
```

這時終端機會出現一行 `No pages found` 的警告，因為還沒有任何頁面，第 1 集建立頁面後就沒事了。

這一章的範例都在這個專案裡寫，`npm run dev` 請一直開著。寫完之後也請把專案留著，第 15 章會回來把管理者的暗號搬到環境變數。
