# 混合渲染：替每一頁挑規則

## 本集目標

在同一個網站裡，替不同的頁面挑選合適的渲染方式，並且會用 `**` 一次設定一整群網址。

## 正文

### 同一個網站，四種做法

到這裡，你的 `nuxt.config.ts` 長這樣：

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  compatibilityDate: "2025-07-15",
  devtools: { enabled: true },
  routeRules: {
    "/about": { prerender: true },
    "/news": { swr: 10 },
    "/blog": { isr: 60 },
    "/dashboard": { ssr: false },
  },
});
```

沒寫在 `routeRules` 裡的頁面（例如首頁），照預設每次請求都在伺服器渲染。同一個網站，每一頁的 HTML 產生方式都不一樣，這就叫**混合渲染**（hybrid rendering）。

### 一次設定一整群網址

網站裡常常有一整群相同性質的頁面，例如每一篇文章。新增 `app/pages/posts/[id].vue`：

```vue
<!-- app/pages/posts/[id].vue -->
<script setup lang="ts">
const route = useRoute();
const { data } = await useFetch("/api/now");
</script>

<template>
  <main>
    <h1>第 {{ route.params.id }} 篇文章</h1>
    <p>產生時間：{{ data?.now }}</p>
  </main>
</template>
```

文章有幾百篇，不可能一個一個寫規則。在 `routeRules` 加一條：

```ts,ignore
    "/posts/**": { swr: 60 },
```

`**` 的意思是「這個位置之後的任何東西」，所以 `/posts/1`、`/posts/2`、`/posts/abc` 全都套用 `swr: 60`。

建置、啟動之後，用 `curl` 依序抓 `/posts/1`、`/posts/2`、`/posts/1`、`/posts/2`，每次間隔一秒。我把結果整理成這樣：

```text
/posts/1 第 1 篇文章 產生時間：08:56:56
/posts/2 第 2 篇文章 產生時間：08:56:57
/posts/1 第 1 篇文章 產生時間：08:56:56
/posts/2 第 2 篇文章 產生時間：08:56:57
```

每個網址各記各的：`/posts/1` 記住的是 `/posts/1` 的內容，不會拿去給 `/posts/2`。

### 怎麼挑

遇到一個新頁面，可以依序問自己這幾個問題：

1. **需要伺服器渲染嗎？** 後台、登入後才看得到、不需要被搜尋的頁面 → `ssr: false`。
2. **內容只有改程式碼才會變嗎？** 關於我們、使用條款 → `prerender: true`。
3. **內容會變，但晚一點更新沒關係嗎？** 最新消息、文章、商品頁 → `swr`（Vercel、Netlify 上用 `isr`），秒數看你能接受多舊。
4. **都不是？** 那就不寫規則，每次請求都在伺服器渲染。

| 頁面 | 規則 | 原因 |
| --- | --- | --- |
| 關於我們 | `prerender: true` | 內容只有改程式碼時才會變 |
| 最新消息 | `swr: 600` | 每天更新幾次，晚 10 分鐘沒關係 |
| 文章 `/posts/**` | `swr: 3600` | 發布之後很少改 |
| 後台 `/dashboard` | `ssr: false` | 自己人用，不需要被搜尋 |
| 留言板 | 不寫 | 送出留言之後要馬上看到 |

### 快取是大家共用的

用 `swr` 之前，有一件事一定要記住：**快取是用網址當作鑰匙的，同一個網址，所有人拿到同一份。**

這代表每個人看到的內容不一樣的頁面，絕對不能用 `swr`。例如一個頁面寫著「你好，小明」，如果它被快取了，下一個打開的人也會看到「你好，小明」。

Nitro 為了防止這種事，在渲染要被快取的頁面時，會把請求的標頭拿掉，其中包括 cookie（瀏覽器存放登入狀態之類資訊的地方）。我實際試過：一個用 cookie 顯示使用者名字的頁面，加上 `swr` 之後，不管帶什麼 cookie 去請求，伺服器渲染出來的都是「訪客」。所以「用了 `swr` 之後登入狀態怪怪的」，通常就是這個原因。

**個人化的頁面，不要用 `swr`、`isr` 或 `prerender`。**

### 留言板該怎麼設

用這個標準看第 14 章的留言板：

- 留言列表頁：送出留言之後，頁面會 `refresh` 重抓一次，使用者期待馬上看到自己的留言。如果頁面被快取，重新整理之後新留言可能不見，使用者會以為沒送出去。所以**不寫規則**，維持每次渲染。
- `/api/...` 那些 API：新增、刪除留言的 API 每次都要真的執行，不能快取。`routeRules` 也可以對 API 設定規則，但留言板的 API 不需要任何規則。

一個網站裡，「哪些頁面可以快取」要一頁一頁想，不是全部設成一樣。

## 重點整理

- 同一個網站裡，不同頁面用不同的渲染方式，叫混合渲染。
- 沒寫規則的頁面，預設每次請求都在伺服器渲染。
- `"/posts/**"` 可以一次替一整群網址設定規則，每個網址各自快取。
- 快取是用網址區分的，所有人共用；個人化的頁面不要用 `swr`、`isr` 或 `prerender`。
