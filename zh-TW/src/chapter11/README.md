# 測試

你寫完一個功能，怎麼知道它是對的？最直接的做法是打開網頁，自己點一點、輸入一些東西，看結果對不對。小專案這樣就夠了。

但專案會長大。三個月後你改了一個元件，要怎麼確定沒有弄壞其他地方？難道每次都把網站從頭到尾手動點一遍嗎？這時候就需要**自動化測試**：把「點這裡、輸入那個、結果應該是這樣」寫成程式，需要的時候一個指令就全部跑完，幾秒鐘內告訴你哪裡壞了。

這一章用的工具，都是 `npm create vue@latest` 勾選 Vitest 時就會幫你裝好的：

- **Vitest**：執行測試的工具。它和 Vite 共用設定，速度很快。
- **Vue Test Utils**（`@vue/test-utils`）：Vue 官方的元件測試函式庫，負責在測試裡掛載元件、找畫面上的元素、模擬點按鈕和打字。
- **jsdom**：在 Node.js 裡模擬瀏覽器，讓元件不用開真的瀏覽器也能渲染。

最後一集測用到 store 的元件時，會再多裝一個 `@pinia/testing`。

這一章的重點不是背一堆 API，而是學會一種想法：**測試要檢查「使用者看得到的結果」**。使用者看到的是畫面上的文字、按鈕、輸入框，不是元件裡的變數叫什麼名字。所以測試裡大多是「按下按鈕，畫面上的數字應該變成 1」這種寫法，而不是去讀元件內部的 `ref`。這樣的測試，就算你把元件內部整個改寫，只要畫面行為沒變，測試就不用跟著改。

這一章用 TypeScript 寫，需要先讀完第 10 章。測試的對象會用到前面學過的東西：props、emit、`v-model`、`onMounted`、composable 和 Pinia。第 2 集會用 create-vue 建立一個新的練習專案 `vue-testing`，這一章的所有範例都放在裡面。
